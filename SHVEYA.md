## Engineering Constitution (не нарушать)
1. Не выдумывать результаты, тарифы, законы без источника + даты
2. Не допускать AI к фин решениям напрямую (цены, списания, возвраты)
3. Не менять цену без версии EstimateVersion
4. Не закрывать заказ без подтверждения возврата
5. Не удалять историю передачи (Chain of Custody)
6. PostgreSQL — единственный SSOT. Redis — только кэш.
7. Вещь не равна заказ. Garment с QR, фото привязано к вещи.

## Как я работаю в v2 (чтобы не слабеть)

### Правило 1: Файловая система больше чем Чат
Чат — это RAM, которая течет. Диск — это мозг. Все важное пиши в /mnt/data/мозг/
Структура:
- 00_CORE/ — SHVEYA.md, BRAIN.md, DECISIONS.md, CONSTITUTION.md
- 01_PLANS/ — PLAN_V5_MASTER, PROGRESS_V5, SOP Ф0.10, RISK Ф0.11, DATA Ф0.12
- 02_MEMORY/ — KNOWLEDGE_GRAPH.md (связи сущностей), LESSONS.md, CONTEXT.md
- 03_TASKS/ — одна задача = один файл, меньше 6K токенов
- 04_CODE/ — код, который читается через local_agent_pro_v2

### Правило 2: Планирование перед кодом (ultrathink)
Перед любым кодом:
1. think hard — 10K токенов на план
2. Запиши план в 03_TASKS/TASK_XXX_plan.md
3. Только потом код

### Правило 3: Изоляция контекста
Одна задача = одна сессия = один файл. Не тащи 100 файлов в один чат.
Используй под-агентов: каждый получает только свой кусок и возвращает summary.

### Правило 4: Токен-бюджет
- Один запрос меньше 6.5K токенов (снижение с 18K на 64% после оптимизации по исследованиям)
- Если файл больше 5K — читай только оглавление + нужные куски через file_search
- Bulk tool results — никогда не в чат, только в файлы

### Правило 5: Second Brain
Каждый день обновляй:
- KNOWLEDGE_GRAPH.md — связи: Order → Garment → Estimate → Delivery → Payment
- DECISIONS.md — почему выбрали b2.medium, почему Shveya Point приоритет
- LESSONS.md — что узнали: доставка 199+199 убивает CM
